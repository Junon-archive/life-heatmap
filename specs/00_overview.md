# 00. 프로젝트 개요 — Life Heatmap

## 한 줄 정의
종이 모눈에 수기로 기록하던 일일 루틴 히트맵(기상/출근 · 퇴근/취침 · 운동 등)을 옮긴 **개인용 정적 웹앱**. 서버 관리 0, 비용 0, 모바일 우선, 칸 클릭 즉시 입력.

## 5대 원칙
1. **일반화된 히트맵**: 용도별 히트맵을 개별 구현하지 않는다. 단일 히트맵 컴포넌트를 사용자가 여러 개 생성·이름 지정·설정하는 구조. 향후 어떤 히트맵이 추가될지 모른다는 전제로 설계한다.
2. **의미 비강제**: 색·빗금·숫자·기호의 "의미"를 앱이 정의하거나 강제하지 않는다. 모든 표기 기능은 모든 히트맵에서 사용 가능하며, 쓸지 말지·무슨 뜻일지는 사용자 재량이다. (의미 기억용으로 히트맵별 범례 기능만 제공 — 기본 숨김.)
3. **Zero-Cost & Local-First**: 무료 티어만 사용(Cloudflare Pages + KV). 입력은 항상 localStorage에 먼저 저장되어 오프라인에서도 완전 동작, 온라인 시 백그라운드 동기화.
4. **입력 마찰 최소화**: 별도 입력 페이지 없음. 히트맵의 칸을 탭하면 그 자리에서 바로 입력. 하루 기록에 3탭 이내를 목표로 한다.
5. **군더더기 없는 디자인**: 모바일 우선, 첫 화면에서 히트맵이 즉시 보임, 장식 최소화. 장기(수년) 사용을 전제로 레이아웃을 설계한다.

## 용어
- **히트맵(Heatmap)**: 사용자가 생성한 기록판 1개. 이름·유형·설정을 가진다.
- **칸(Cell)**: 하루 = 한 칸. 채우기 + 마크 + 테두리 강조 상태를 가진다.
- **채우기(Fill)**: 칸의 배경. 없음 / 빗금(hatch) / 단색(solid) × 팔레트 색상.
- **마크(Mark)**: 칸 중앙의 오버레이. 숫자 **또는** 기호(○/X/★) 중 하나.
- **유형(Type)**: 일반(basic) / 연속일수형(streak) / 조건부형(conditional).
- **주(Week)**: 일요일 시작, 7칸 1행. 위→아래로 과거→현재.

## 프라이버시 전제
- 배포 URL을 아는 타인이 접속해도 **빈 앱**만 보인다(데이터는 localStorage + 비밀 동기화 코드로 연결된 KV에만 존재).
- 민감한 히트맵은 사용자가 위장 이름을 붙여 쓴다. 앱은 이름을 절대 고정하지 않는다.
- **주의**: 문서·코드·커밋 메시지 어디에도 개인 기록의 실제 용도를 유추할 수 있는 단어를 쓰지 않는다. 히트맵 명칭은 항상 사용자가 붙인 이름(예: "퇴근/취침") 그대로만 언급한다. GitHub 저장소는 private 권장.
