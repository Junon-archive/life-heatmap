# 01. 확정 요구사항 & 결정 로그

사용자와의 대화(2026-08-16)에서 확정된 사항. 구현 시 임의로 변경하지 말 것.

## 1. 히트맵 관리
- [R-01] 히트맵은 단일 일반화 컴포넌트. 사용자가 **추가/이름 변경/순서 변경/삭제** 가능.
- [R-02] 이름은 항상 사용자 지정(기본값 placeholder만 제공). 앱이 용도별 이름을 고정하지 않는다.
- [R-03] 생성 시 유형 선택: 일반 / 연속일수형 / 조건부형. 유형은 생성 후에도 설정에서 변경 가능해야 한다(데이터는 보존).
- [R-04] 초기 사용자는 3개를 만들 예정(기상/출근, 퇴근/취침, 운동)이지만 앱은 개수 제한 없음.

## 2. 칸 표기 체계
- [R-05] 채우기: 없음 / **빗금** / **단색** × 팔레트 색(03 문서에서 6색 확정).
- [R-06] 마크: **숫자(사용자 직접 입력) 또는 기호(○, X, ★) 중 하나만**. 숫자+기호 동시 표시는 하지 않는다(사용자 확인 완료). 마크 색상 선택 가능.
- [R-07] **테두리 강조**는 마크와 별개의 독립 토글 — 채우기·마크와 자유 조합 가능. (숫자/기호가 중앙 슬롯을 두고 경쟁하는 문제를 테두리를 분리해 해결.)
- [R-08] 한 칸 = 채우기(0~1) + 마크(0~1) + 테두리(on/off) 조합. 예: 빗금+숫자2, 단색+○+테두리.
- [R-09] 모든 표기 기능은 모든 히트맵에서 제공. 특정 히트맵이 특정 기능을 쓰지 않는 것은 사용자 재량이며 앱이 막지 않는다.

## 3. 유형별 동작
- [R-10] **일반(basic)**: 수동 표기만. 부가 로직 없음.
- [R-11] **연속일수형(streak)**:
  - 별도의 **실패 체크**가 존재. 실패 체크는 streak를 끊고 **채우기(자동 그라데이션 포함)는 가질 수 없지만, 마크(숫자/기호)와 테두리 강조는 함께 표기할 수 있다**(D-10).
  - 미입력 빈칸은 streak를 끊지 않는다. streak = **마지막 실패 체크 다음 날부터 오늘까지의 달력일수**.
  - 채색 모드는 **생성 시(및 설정에서) 자동/수동 중 선택**:
    - 자동(auto): 마지막 실패 이후 지난 날들이 자동으로 그라데이션 채색. 매일 입력 불필요.
    - 수동(manual): 사용자가 직접 채운 날만 채색(채색 강도는 계산된 streak 단계를 따름). streak 계산 자체는 자동 모드와 동일.
  - 연속일수가 길수록 색이 **점점 진해지는 그라데이션**(단계는 03 문서).
  - **마일스톤 일수는 히트맵마다 사용자가 지정**(기본 제안값: 7, 30, 50, 100, 365). 해당 일차의 칸에 테두리 이펙트.
  - **"현재 연속 N일"** 을 히트맵 카드에 상시 표시.
- [R-12] **조건부형(conditional)**: 칸에 수치를 입력하면 사용자가 정의한 threshold 구간 규칙에 따라 자동 채색(예: 수면 ≤6h 경고색, ~8h 보통, ≥10h 진한 색). 구간 규칙은 히트맵 설정에서 편집. 수치 표시 여부 토글.

## 4. 입력 UX
- [R-13] 입력 페이지와 조회 페이지를 분리하지 않는다. **칸 탭 → 그 자리에서 편집기(바텀시트/팝오버) 표시 → 즉시 저장**.
- [R-14] 과거 날짜 수정 자유. **미래 날짜도 입력 가능(잠금 금지)** — 미리 표기할 일이 있음.
- [R-15] 과거 기록(2026-07-05~현재)은 사용자가 UI로 직접 입력한다. 별도 임포트 기능 불필요.

## 5. 화면/디자인
- [R-16] 첫 화면에서 주요 히트맵이 바로 보인다. 모바일은 화면 한계 시 1개씩 표시 + **좌우 스와이프 전환**. 데스크톱은 여러 개 나란히.
- [R-17] 주 시작 = **일요일**. 1행 = 7칸. 새 주는 아래로 추가.
- [R-18] 행 라벨은 **날짜 범위(7/5~7/11) ↔ 주 번호(W28) 토글** (전역 설정, 저장됨). 주 번호 규칙: 1월 1일이 포함된 일요일 시작 주 = W1 (사용자의 종이 기록 W28=2026-07-05 주와 일치 확인됨).
- [R-19] 장기 표시: 기본은 최근 N주 + **위로 스크롤하면 과거 로드** + **연도 점프 버튼**.
- [R-20] 접속 시 오늘 칸이 보이는 위치로 자동 스크롤하되, **오늘 행이 화면 최상단에 오지 않게** — 과거 행들이 위에 함께 보여야 한다(오늘은 보이는 영역 하단부에 위치).
- [R-21] 상태의 시각 구분: 지난 날짜의 빈칸 / 오늘 / 미래 칸을 디자인으로 구분(03 문서). "실패라서 빈칸"과 "안 지난 날"의 혼동을 줄인다.
- [R-22] 군더더기 없이 깔끔하게. 색은 너무 많지도 적지도 않게(6색 팔레트). 모바일 환경 최우선.
- [R-23] 종합 기능·설정 관리 페이지는 필요하므로 둔다(설정 뷰).

## 6. 데이터/동기화
- [R-24] 서버 관리 없는 정적 사이트. 데이터는 localStorage가 1차 저장소.
- [R-25] **폰+PC 동일 데이터 공유**: Cloudflare Pages Functions + KV로 자동 동기화(사용자 확정). 비밀 동기화 코드를 아는 기기만 데이터에 접근. local-first — 오프라인 완전 동작, 온라인 시 백그라운드 동기화.
- [R-26] **JSON 내보내기/가져오기** 백업 기능 기본 탑재.

## 7. 부가 기능
- [R-27] **범례(legend)**: 히트맵별로 "이 표기 = 이 의미" 메모. **기본 숨김**(위장 유지), 아이콘 탭으로 열람. (사용자: "확실히 필요")
- [R-28] **PWA 필수**: 홈 화면 설치, 오프라인 동작.
- [R-29] **통계 뷰**: 상세 설계는 위임받음(03 문서 §7). 방향: 히트맵별로 월/분기 단위 표기 비율(채움 %, ○ %, X % 등)과 숫자 합계, streak형은 현재/최고 기록. 디자인 깔끔하게.
