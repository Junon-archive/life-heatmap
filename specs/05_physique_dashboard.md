# 05. 신체 대시보드 (세 번째 뷰)

주기적으로 신체 측정값을 입력하면 현재 상태·추세·목표 대비 진행을 보여주는 대시보드.
사용자의 엑셀("여명 프로젝트_신체 비율.xlsx")을 웹으로 이관·개선한 것. 목업: `temp/physique_mockup.html` (구성·테마 확정본, 2026-08-20 사용자 승인).

## 1. 범위와 원칙
- Life Heatmap 앱 안의 **세 번째 뷰**. 헤더 세그먼트가 「기본 | 연간 | **신체**」 3개로 확장된다.
- 테마·컴포넌트는 본 앱(specs/03 §4 쿨 그레이)을 그대로 따른다. 목업의 다크 테마는 무시.
- 사이드바·별도 페이지 없음. Insight(자동 조언) 패널 없음.
- 데이터·동기화·백업은 기존 인프라(localStorage + KV, specs/02)를 재사용 — 같은 문서에 실린다.
- 기존 데이터 이관 기능 불필요: 사용자가 UI로 직접 재입력한다.

## 2. 지표
| 키 | 이름 | 단위 | 비고 |
|---|---|---|---|
| `weight` | 체중 | kg | |
| `bodyFat` | 체지방률 | % | |
| `shoulder` | 어깨 폭 | cm | |
| `muscle` | 골격근량 | kg | |
| `waist` | 허리 둘레 | cm | |
| `arm` | 팔 둘레 | cm | |
| `ratio` | 어깨/허리 비율 | (무단위) | **파생값** = `ROUND(2.304 × shoulder ÷ waist, 2)`. 2.304는 어깨 폭→둘레 환산 계수(사용자 확인) |

- 허벅지 둘레는 **제외**(사용자 결정). 엑셀에 있었으나 이관하지 않는다.
- 지표 목록은 v1에서 고정(사용자 정의 지표 추가는 백로그).

## 3. 데이터 모델 (specs/02 문서에 추가되는 부분)

AppData 최상위에 `physique` 섹션을 추가한다:

```jsonc
"physique": {
  "u": 1765000000000,            // goals/targetDate 수정 시각 (LWW)
  "targetDate": "2026-11-30",    // 목표 날짜 (사용자 편집 가능)
  "goals": {                      // 지표별 목표값. ratio 포함 7개
    "weight": 68, "bodyFat": 12, "shoulder": 51,
    "muscle": 37, "waist": 75, "arm": 37.5, "ratio": 1.6
  },
  "entries": {                    // key: YYYY-MM-DD (하루 1개)
    "2026-08-19": {
      "weight": 75.3, "bodyFat": 19.7, "shoulder": 46,
      "muscle": 35, "waist": 92, "arm": 34.5,   // 전부 옵션 — 빈 지표는 키 자체를 넣지 않는다
      "u": 1765000000000          // 엔트리 수정 시각 (LWW)
    }
  }
}
```

- **부분 입력 허용(핵심)**: 한 기록에 값이 있는 지표만 저장한다. 모든 계산은 지표별 독립 시계열로 동작한다(§5).
- `ratio`는 저장하지 않는다 — 항상 파생 계산.
- 모든 지표를 지운 엔트리는 `{u}`만 남긴 "지움" 엔트리로 유지(동기화 전파, specs/02 §3와 동일 규칙).
- **미래 날짜 입력 금지**: 입력 날짜는 오늘 이하만 허용. (엑셀에서 임의 미래값이 "최신값"을 오염시킨 문제의 재발 방지 — D-18)
- **병합(LWW)**: `goals`/`targetDate`는 `physique.u`, 엔트리는 날짜별 `u` 기준. specs/02 §5.3에 병합 단위로 추가된다. 백업 내보내기/가져오기에도 자동 포함.
- 마이그레이션: 기존 문서에 `physique`가 없으면 로드 시 기본값(빈 entries, 위 목표값을 초기 기본으로)으로 보강.

## 4. 화면 구성 (위→아래, 목업 확정)

1. **히어로 행 (3장)**
   - **대표 지표 카드**: 어깨/허리 비율 — 현재값/목표, 시작→목표 트랙 바, 목표까지 남은 양.
   - **D-day 카드**: 목표일까지 남은 일수. 목표일이 지났으면 "D+N" 표기.
   - **종합 진행률 링**: §5의 종합 진행률. 부제 "시작값 → 목표값 기준, 7개 지표 평균".
2. **지표 카드 6장** (weight/bodyFat/shoulder/waist/muscle/arm — ratio는 히어로 전담): 현재값, 총 변화 배지(시작 대비, 변화 없으면 amber ±0), 진행 바, 시작/목표. 현재값의 측정일이 해당 지표 기준 최신 기록 날짜와 다르면(다른 지표만 갱신된 경우) 작은 날짜 뱃지 표시.
3. **추세 차트 + 목표 예측**
   - 추세: **정규화 축**(시작=위, 목표=아래) SVG 라인 차트. 탭 [종합/체중/허리/골격근/비율] — 종합은 체중+허리+골격근+비율 4선, 개별 탭은 해당 지표 1선(실제 값 축 라벨 병기). 마지막 점부터 회귀 연장 점선(목표일까지). 차트 라이브러리 금지 — 자체 SVG. (2026-08-20 사용자 요청으로 종합에 허리 추가·골격근 탭 신설)
   - 목표 예측: 지표별 예상 달성일 목록. 색: 목표일 이내 `good`(녹) / 목표일 +30일 이내 `close`(amber) / 그 외 `late`(rose). 주당 속도 병기. 계산 불가 사유 표기(§5).
4. **필요 페이스 vs 현재 페이스**: 지표별 이중 막대(회색=필요 속도, 파랑=현재 회귀 속도) + 수치 `현재/필요 단위·주`. 방향 화살표(↓ 감소 목표, ↑ 증가 목표).
5. **최근 기록 테이블**: 최신순. 열: 날짜, 체중, 체지방, 허리, 비율(+ 나머지는 폭에 따라). 값이 없는 칸은 `–`. **행 탭 → 해당 날짜의 입력 모달(수정 모드)**.

**입력 모달**: 헤더 우측 상단 **＋ 버튼**(신체 뷰에서는 "측정 추가"로 동작 — 다른 뷰에서는 기존대로 히트맵 추가) 또는 기록 행 탭으로 열림. 구성: 날짜(기본 오늘, 오늘 이후 선택 불가) + 6개 숫자 입력(빈 칸 허용) + 저장/취소 + 삭제(수정 모드). 비율 자동 계산 안내 문구. 같은 날짜에 다시 저장하면 그 날짜 엔트리를 덮어쓴다(하루 1기록).

**목표 편집**: 설정 뷰(⚙)에 "신체 목표" 섹션 추가 — 7개 목표값 + 목표 날짜 편집.

**빈 상태**: 기록 0개면 대시보드 대신 "＋로 첫 측정을 기록하세요" 안내 + 목표 설정 바로가기.

## 5. 계산 규칙 (결측 처리 포함 — D-19, D-20)

모든 계산은 **지표별 독립 시계열**로 수행한다. `series(m)` = 해당 지표 값이 있는 엔트리를 날짜순 정렬한 것.

- **ratio의 시계열(사용자 확정)**: `shoulder`와 `waist`가 **같은 엔트리에 모두 있는 날만** 점을 만든다. 한쪽만 있는 날은 비율 계산에서 제외. 히어로의 "현재 비율"도 이 시계열의 마지막 점이다(최신값 조합 사용 금지).
- **시작값** = series 첫 값, **현재값** = series 마지막 값 (지표마다 날짜가 다를 수 있음).
- **진행률(지표)** = `clamp01((현재-시작)/(목표-시작))`. series가 비었거나 목표=시작이면 제외.
- **종합 진행률** = ratio를 **포함**한 7개 지표 중, 진행률이 계산되는 지표들의 평균(엑셀의 비율 누락은 실수였음 — 사용자 확인).
- **추세(회귀)** = 전 기간 최소제곱 선형 회귀(x=날짜, y=값). **점 2개 이상**일 때만. 주당 속도 = 기울기×7.
- **예상 달성일** = 회귀선이 목표값에 도달하는 날짜. 계산 불가 조건: 점<2("데이터 부족"), 기울기≈0 또는 목표 반대 방향("현재 추세로 도달 불가"). 예상일이 5년 이후면 "'YY M월+" 축약.
- **필요 페이스** = `(목표 - 현재값) ÷ 목표일까지 남은 주수`. 목표일이 지났으면 "-" 처리.
- **D-day** = `targetDate - today`(달력일).
- 4주 창 방식(엑셀)은 쓰지 않는다 — 측정이 성겨서 노이즈가 큼(D-19).
